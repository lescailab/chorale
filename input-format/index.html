The input data

Matrices, sample tables, organisms, phenotypes, nuisance variables, and exchangeability.

Two tables go in per modality: a feature-by-sample matrix of measurements, and a sample table with one row per sample. Nothing about the organism, the assay or the condition is assumed, and no column name beyond the two below is required.

The modalities are measured on different individuals, so what connects them is a fixed vocabulary of named biological concepts rather than a shared sample. A concept is a set of features that belong together for a stated biological reason, and every modality is scored on the same concepts. A modality therefore has to supply two things: measurements its samples can be compared on, and feature identifiers that reach the vocabulary.

The container the tables become

chorale_load() puts the two tables into a SummarizedExperiment, which is the container every later step reads:

se <- chorale_load(matrix, samples)
SummarizedExperiment::assay(se)    # the measurements
SummarizedExperiment::colData(se)  # the sample table

This is Bioconductor’s standard structure for a feature-by-sample assay with its sample annotation, and using it has three consequences. The measurements and the sample table are one object, so they cannot be subset, reordered or filtered out of alignment with one another. Feature and sample identifiers stay bound to the numbers rather than living in a separate vector. And a study whose data already sit in a SummarizedExperiment is in the right shape, as is one using a subclass such as a DESeqDataSet or a SingleCellExperiment:

se <- chorale_load(SummarizedExperiment::assay(existing),
                   as.data.frame(SummarizedExperiment::colData(existing)))

chorale_load() is the route in because it also resolves the design labels into one vocabulary, as described below. An object built by hand can be passed to chorale_concept_fit() directly, provided its colData already carries the required columns in canonical form.

The measurement matrix

Features in rows, samples in columns, and colnames(matrix) equal to samples$sample_id in the same order. A modality is whatever was measured on its own set of samples: a transcriptome, a proteome, a lipidome, a panel of variant dosages. Each is one matrix and one call.

Row names are the feature identifiers, and they are what reaches the vocabulary of concepts. Gene and protein modalities are mapped to Entrez identifiers by chorale_map(), from Ensembl identifiers, symbols or UniProt accessions. A lipidome is declared with feature_space = "lipid" and reaches the same concepts through its class names instead.

How many features a modality has for a concept decides whether it can be scored on that concept at all. chorale_concepts() reports that count for every concept and every modality, so a modality whose annotation reaches little of the vocabulary is visible before anything is fitted rather than afterwards as an absence of results.

Missing values are permitted. Each feature is centred and scaled before decomposition, and an entry that is not finite afterwards is set to the feature mean, so a feature observed in few samples contributes little and adds noise in its place. Filter on detection rate before loading.

The scale each matrix is on

Two different jobs are involved, and only the second is done for you.

Between samples. Samples must already be comparable within the modality, because standardisation acts on a feature across samples and cannot remove a difference in library size or in total ion current. Apply the modality’s own normalisation first: size factors, CPM or TPM for sequencing counts, total-intensity or median scaling for mass spectrometry.

Within a feature. The measurement scale is read from the matrix, so no particular unit is required. transform = "auto", the default, chooses per modality:

What the matrix holdsAppliedReason
Integer counts spanning orders of magnitude: raw sequencing counts, spectral countsvstUnder Anscombe’s transform a Poisson variance no longer grows with the mean, so a highly expressed feature stops dominating an axis for no biological reason.
Positive continuous values, right-skewed: TPM, FPKM, RPKM, normalised LFQ intensities, peak areaslogLabel-free intensities span orders of magnitude. log1p is used, which keeps zeros finite.
Values already on a symmetric scale: log ratios, log intensities, z-scores, variant dosagesnoneAlready symmetric, and a further transform would distort it.

The rule is mechanical. Any negative value means the matrix is already on a symmetric scale and nothing is applied. Otherwise, whole numbers whose 99th percentile exceeds five times their median take the variance-stabilising transform; a skewness above one with the same spread takes the logarithm; anything else is left alone. What was applied is recorded in the fit.

Where the matrix is not what its distribution suggests, say it explicitly, one value per modality:

fit <- chorale_concept_fit(containers, sets,
                           transform = c(RNA = "vst", PROT = "log", METAB = "none"))

What every modality must carry

ColumnMeaning
sample_idUnique within the modality, and matching the matrix column names in order.
phenotypeThe contrast being estimated, on at least two levels.

The phenotype is a condition of entry rather than a covariate. The estimand is a contrast, so a modality that cannot express one cannot contribute to it, and a run whose modalities do not all carry it stops with that named as the reason.

The column need not literally be called phenotype. Its role and reference level are analysis settings:

control <- chorale_control(
  phenotype_column = "outcome",
  phenotype_reference = "reference"
)
fit <- chorale_concept_fit(containers, sets, control = control)

The phenotype may be any estimable categorical comparison: treatment response, exposure group, genotype class, time category, or another study-defined outcome. Every modality must contain the declared reference and at least one comparison level.

What every other column does

Every remaining column is a possible covariate. Eligible covariates enter the model the concept score is regressed on, so the reported phenotype effect is adjusted for them. Excluded covariates are reported with a reason: absent modality, incompatible type or levels, excessive missingness, or lack of joint estimability.

How a covariate is read follows from its type in the sample table, so the type is what needs getting right.

Stored asRead asWhat it contributes
Character or factorCategoricalOne adjusted coefficient per level beyond a common reference, on the levels every modality realises.
Numeric in every modalityContinuousOne adjusted slope after the covariate is standardised.
A number stored as textCategoricalThe values become levels, so two cohorts recording the same age as 6 and 6.0 share none. A continuous covariate stored as text is read this way, which is the common mistake.

The design is read as supplied. A study that wants a continuous covariate treated in bands supplies the bands as a column of their own, which keeps the choice of cut points with the person who knows what they mean.

Two column names are treated as bookkeeping rather than biology and never anchor a comparison: sample_id and modality. A column holding a distinct value for nearly every sample identifies the sample rather than grouping it, and is dropped for the same reason.

One set of words for the design labels

Cohorts assembled by different groups can record the same thing differently. CHORALE maps only unambiguous general labels, such as ctrl to control and male to M. Study-specific meanings are never guessed.

Labels are therefore resolved as the data are read.

CovariateResolves to
phenotypecase, control
sexF, M
genotypecarrier, non-carrier

The registry holds only terms general across biology. Names particular to one organism, model or study are absent by design, since a tool carrying the labels of the data it was built on fits nothing else. A study whose labels are not covered supplies its own:

registry <- chorale_label_registry()
registry$phenotype <- c(registry$phenotype, "study_case" = "case")
registry$treatment <- c("drug" = "treated", "placebo" = "untreated")
se <- chorale_load(matrix, design, labels = registry)

A label the registry does not recognise is left as it is. Two cohorts using different unrecognised labels for the same thing share no level, which is a silent way to recover nothing, so chorale_check_design() reports what a collection can and cannot anchor on before anything is fitted.

Genotype beside phenotype

Where a design records genotype separately from phenotype status, the phenotype remains the contrast being estimated and genotype enters as one more covariate the effect is adjusted for. A study whose primary contrast is the genotype puts it in the phenotype column, since that column names the role rather than the measurement.

Organism and annotation

Nothing in the estimator is tied to an organism. Gene identifiers are mapped through whichever Bioconductor annotation the study needs, and the curated vocabulary is retrieved for whichever species it describes.

# Mouse-native collections and mouse annotation.
mouse_map <- chorale_map(rownames(matrix), from = "ENSEMBL",
                         orgdb = "org.Mm.eg.db")
mouse_sets <- chorale_genesets(species = "Mus musculus", db_species = "MM")

# Human collections and human annotation.
feature_map <- chorale_map(rownames(matrix), from = "ENSEMBL",
                           orgdb = "org.Hs.eg.db")
sets <- chorale_genesets(species = "Homo sapiens", db_species = "HS")

Another annotated organism uses its Bioconductor OrgDb. Curated collections can come from a compatible source database or be supplied as custom Entrez sets:

other_map <- chorale_map(rownames(matrix), from = "SYMBOL",
                         orgdb = "org.Species.eg.db")
custom_sets <- list(
  concept_a = c("101", "102", "103", "104", "105"),
  concept_b = c("201", "202", "203", "204", "205")
)
sets <- chorale_genesets(collections = character(), custom = custom_sets,
                         min_size = 5)

The vocabulary is an argument, so a collection can be analysed in curated pathways, in cell type signatures, in a set of concepts defined for the study, or in any combination of them. What the vocabulary contains bounds what the concept channel can express, which is why it is chosen before the data are looked at.

The lipid-to-pathway table takes its compound annotation from one organism, but it is keyed on set names that are the same across species. A lipid is therefore placed in the set a study of any organism would use, wherever that pathway exists in it. A table of the same shape built for another organism is supplied in its place.

Conditions on what is supplied

Matrices are normalised within each modality before they are loaded. A cross-modal transformation that uses the intended answer, or constructed sample pairs, puts information into the scores that the design is then asked to find in them, so scoring must see each modality on its own. Batch and study variables belong in the design, where their effects are adjusted and reported.

Shared covariates, local nuisance, and exchangeability

These three ideas are related but not interchangeable.

  • A shared covariate is represented compatibly in every modality and enters the regression model for concept and joint evidence.
  • A modality-local nuisance variable is recorded only for one modality. It can be removed from that modality’s concept scores before joint stacking.
  • An exchangeability block states which samples may exchange residuals under permutation. It describes sampling or dependence, not merely adjustment.
state <- chorale_joint_state(
  fit$encoding,
  n_components = 2,
  nuisance = list(modality_a = c("local_batch", "processing_day"))
)

control <- chorale_control(
  exchangeability_blocks = c("subject_group", "processing_block")
)

Do not infer exchangeability blocks from every design column. A continuous age column would create one-sample blocks and prevent meaningful permutation. Declare only restrictions justified by the way observations were sampled or processed. Missing nuisance values are not imputed: samples unavailable to the local nuisance model retain their original score.

Preflight checklist

Before fitting, verify that matrix columns match sample_id, the phenotype contrast exists in every modality, numeric covariates are stored as numeric, identifier mapping reaches the intended concepts, and all transformations and normalisations are recorded. Run chorale_check_design() and inspect chorale_concepts()$coverage. These checks distinguish a weak biological signal from a question the inputs never made estimable.
